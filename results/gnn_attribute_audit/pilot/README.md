# Pilot and reproduction investigation

Pilot: the first two programs of every suite (12 programs), null mode and
GNN seed 42, in the `cgym-gnn:0.2.5` container (CompilerGym 0.2.5, LLVM 10,
torch 2.13.0+cpu, torch-geometric 2.8.0.post1, amd64 under Rosetta).
Records of that first pilot are kept in `records_null_v1_global_index/`
and `records_gnn_seed42_v1_global_index/`; they were produced with the
six-suite global index as the torch-seed index and are superseded.

Findings.

- Inputs: every program's O0 and Oz observation matched the stored battery
  values; the exported module reloaded through a content-specific
  `file://` URI with identical IR; adding `minsize optsize` to the
  definitions left the O0 IC unchanged. No failed candidates.
- Argmax rollouts reproduced the stored `argmax_ic` on 12/12 programs, so
  the checkpoint, graph parser, environment and model numerics are
  consistent with the original run.
- Sampled rollouts reproduced the stored eight sample ICs exactly on 6/12
  programs (blas, chstone, mibench) and not on csmith, npb, poj104.
  `index_test.py` and `index_search.py` searched the torch-seed index
  `i` (seed = 42*100000 + i*100 + j) and found exact 8/8 reproductions at
  i = 50 for csmith-v0/1, 51 for csmith-v0/12, 0 for npb-v0/1 and 206 for
  poj104-v1/10/1069 (outputs in `index_*_output.txt`). Together with the
  reproducing suites (blas 0.., chstone 50.., mibench 90..) this is
  consistent with `scripts/evaluate_policy_battery.py` having been run in
  three invocations that enumerate the eligible programs of the suites
  given to `--suites` in sorted order while counting programs whose record
  already exists: NPB alone; blas, csmith, npb, poj104; then all six
  suites. The reconstructed index is stored as `eligible_index` in
  `../programs.json` and every full-run record reports whether the eight
  stored samples were reproduced.
- After the full campaign, NPB reproduced only 21 to 38 of 120 programs
  per seed (all other suites 120/120 equivalent). `index_test_npb.py`
  (output `index_test_npb_output.txt`) shows the true NPB offset is 78
  (blas 50 + csmith 28: NPB was in the four-suite invocation, not alone);
  npb-v0/116 and npb-v0/94 reproduce 8/8 with i = 78 + position. The
  offset-0 "reproductions" were tiny modules whose ICs do not depend on the
  draw. The script now uses 78; the supplementary rerun lives in
  `../npb_offset78/`; the main campaign records are unchanged.
- Timing under emulation: 25 to 100 s per program for both conditions of
  one seed (18 rollouts), 9 to 30 s per program for the null mode.
- On all 12 pilot programs the sampled ICs were identical with and without
  attributes, for the GNN and for the random sequences; only the `-Oz`
  reference and the generated bytes changed.
